# Auto-Test 仓库与历史方案审计

> **Legacy 已移除、不可执行、仅供历史参考。**

审计日期：2026-07-28

## 1. 结论

旧项目的主要问题不是缺少 AI 能力，而是缺少可靠的输入契约、执行契约和结果判定边界。项目先后尝试了运行时 Agent、规则脚本、AI 修复、录制后重放等方案，但始终没有建立以下不变量：

1. 导入必须按表头映射并验证，不能按固定列号猜测。
2. 操作失败必须立即传播，不能只记录日志后继续。
3. 录制必须通过完整校验才能成为可回放资产。
4. 每条通过用例必须有明确、可重试的断言。
5. AI 不得修改测试预期，也不得把产品缺陷修复成测试通过。
6. 有副作用的流程必须具备白名单、检查点、精确对象匹配、清理和恢复。

因此，旧 `platform/` 不继续修补。新 MVP 从输入契约和 IR 开始重建，使用 Playwright Test 作为确定性执行底座。

## 3. Git 主线实现审计

### 3.1 实际验证范围

旧 README 声称已完成 3576 条导入、结构化和确定性回归，但 SQLite 数据显示：

- `test_case` 共 3578 条；
- 只有 2 条处于 `interpret_status=done`；
- 只有 1 条具有 `resolved_steps`；
- 只有 1 条为 `record_status=recorded`；
- 唯一录制并回放的用例是本地 fixture 登录页。

因此，旧主线仅验证了框架能运行一个人工构造的 fixture，没有证明真实历史用例可执行。

### 3.2 会产生假通过的缺陷

旧浏览器工具在点击、输入和选择失败时返回 `{ isError: true }`，而不是抛异常。录制器与确定性执行器只等待工具调用结束，没有检查 `isError`，会把真实操作失败记作步骤成功。

同时存在以下问题：

- 录制结束无条件把用例写成 `recorded`，不要求全部步骤和断言解析成功；
- 多级导航 Agent 失败后仍把当前 URL 记录成目标 URL；
- 未知动作统一降级成点击；
- `wait` 步骤实际不等待任何条件；
- AI 定位在找不到目标时仍被要求返回“最接近”的元素；
- 文本断言退化为在整页查找预期词，容易产生上下文错误；
- 没有断言的用例可以通过；
- CDP 模式共享浏览器上下文，没有可靠的账号、数据和用例隔离；
- 运行状态即使用例失败也统一写为 `done`。

这些缺陷解释了为什么继续增加定位规则和特殊组件补丁没有改善整体可信度。

## 4. 历史批量方案审计

`run_tests/v11_run.log` 是最完整的一次批量执行记录：

- 待执行 3143 条；
- 运行 361.3 分钟；
- 通过 76 条；
- 失败 3060 条；
- 跳过 7 条；
- 通过率约 2.4%。

失败粗分为：

- 1966 条运行异常；
- 625 条找不到元素或执行动作失败；
- 467 条预期文本未满足；
- 后半程出现 `Page.evaluate: Target crashed`，浏览器崩溃后仍继续处理剩余用例。

部分通过记录只验证“页面正常加载”或任意关键词存在，不能作为真实业务通过证据。该方案还在实验脚本中硬编码过 API 密钥和网站凭据，相关密钥应视为已暴露并轮换。

## 5. Excel 样本审计

真实样本至少存在四种结构：

1. 旧版 16 列后台用例，包含项目和端口；
2. 当前 14 列后台/用户端用例；
3. 8 列简化模板；
4. 7 列、带内嵌图片公式的跨系统流程表。

主要数据质量问题：

- 同一含义的列名和列数不一致；
- 部分用例 ID 为空；
- 多行步骤被保存为 `&#10;`；
- 某些模板的全部中文被保存为 HTML 数字实体；
- 前置条件通过自然语言引用其他用例；
- 步骤和预期常把多个动作、多个断言写在一个句子中；
- 测试数据中直接出现账号、密码、手机号和设备标识；
- 有些流程跨多个网站，并包含创建订单、强制停止和结算等真实副作用；
- 图片公式是需求证据，但现有解析器只读取单元格文本。

旧导入器按固定列号读取。只要输入从 16 列改为 14 列，字段就会整体错位，且不会报错。新导入器必须按规范化表头映射，并在导入前生成诊断报告。

## 6. 可保留的工程经验

后期的充电闭环脚本完成过真实订单的启动、停止、占位费生成、结算和收尾复查，其 19 个逻辑测试通过。该实现不能直接成为通用引擎，但验证了以下原则：

- 执行前验证环境、设备和计费配置；
- 用精确订单 ID 而不是页面模糊文本关联对象；
- 对真实手机号和设备使用显式白名单；
- 每个阶段写入私有状态检查点；
- 进程异常后先恢复旧流程，再创建新副作用；
- 多个候选对象时停止，不猜测、不批量操作；
- 每个账号使用独立 BrowserContext；
- 完成后验证没有遗留活跃对象。

这些能力在新 IR 中体现为 `risk`、`dependencies`、`dataBindings`、`cleanupSteps` 和执行策略。

## 7. 清理结果

- 真实输入样本移至仓库外的私有输入目录，目录权限为 `0700`；
- 旧代码、实验脚本、日志、结果和外部仓库副本移至仓库外的私有审计目录；
- Git 历史仍保留旧 `platform/` 的全部提交，可按提交号回溯；
- 新工作树只保留新方案的文档和 Schema。

旧实验中使用过的第三方 API 密钥以及硬编码网站凭据应进行轮换，归档不得重新加入 Git。
